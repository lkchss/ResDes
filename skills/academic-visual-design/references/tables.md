# Tables

For choices about orientation, precision, hierarchy, density or disciplinary conventions, read [table design evidence and examples](design-evidence/tables.md). Use the [original synthetic casebook](design-evidence/casebook/index.html) when a concrete precision or table-versus-figure example helps; it is teaching material, not a fixed template or a validated benchmark.

Identify the unit of observation, rows, columns, headers, grouping, units, notes and intended comparison before changing layout. Keep full underlying precision even if displayed values are rounded. Preserve sample sizes, denominators, missing values and exclusions, estimate definitions, uncertainty type and level, and category mapping. A dash, blank and zero can mean different things: preserve or explain their meaning. Distinguish raw counts from percentages and state the denominator or calculation when needed.

Trace one actual comparison through the proposed cells. If readers must repeatedly relocate comparators, consider a different row/column arrangement or grouped blocks; weigh reduced search against added height, width and repeated headers. Preserve effective parent/subordinate grouping rather than repeating labels mechanically. Put shared statistic definitions near the values or headers when that avoids repeated note lookup. Separate reading instructions, scientific qualifications and attribution into scannable notes without dropping meaning. Choose rules and precision for this content and destination, not a universal aesthetic.

Align comparable quantities by decimal position or right edge, with consistent displayed precision within a meaningful measure group. Do not force counts, probabilities and interval bounds to share a precision rule. Keep a clear row-label stub; indent subordinate rows rather than repeating long parent labels. Use spanning headers to group models or outcomes only when the grouping conveys actual structure. Keep units near their measure, exceptional qualifications beside affected cells, and shared definitions or uncertainty conventions in notes.

For exact value lookup or several measures with different units, a table often serves readers better than a plot. For ranking or the shape of a distribution, consider a figure if the evidence supports it. Address excess width by shortening repeated wording, reorganizing grouped headers, transposing when the comparison remains clear, or splitting into labelled panels with repeated headers before shrinking type. Keep model identities and every value traceable through a split.

For example, a ten-column model table squeezed to unreadable type -> two coordinated panels with repeated row labels and model identifiers, because legible comparison matters more than one uninterrupted rectangle. Preserve all models, observations and notes; apply the target's actual column limit rather than assuming every journal shares one.

Use the user's working format when practical. When the destination requires editable tables, deliver native editable cells or an appropriate source format rather than a screenshot or flattened image. Inspect the rendered table at intended size and check that headers, notes, symbols, rows, columns and page breaks survive export. For conversions, compare cells and notes against the source, explain any intentional presentation changes, and flag anything unrecoverable instead of guessing.
